📋 Build notes — Project media rail

Implementation prompt for the left sidebar. Goal: turn the mockup's rail into working product code in the FinalCap web app (yishengjiang99/finalcut). Client-side only — no server API changes.

What we're building

  • Project media library — every uploaded clip as a row (thumbnail, name, duration, original/result + video/audio badge). Clicking a row selects the active source for the next edit.
  • + Add media — upload entry point; reuses the existing upload flow.
  • Recent jobs — completed outputs (videos, SRTs) with relative timestamps; click to preview, download, or reuse as a new source.

Current code reality

  • src/App.jsx: uploadedVideos = [{data: Uint8Array, url, name, mimeType, isAudio}]; videoFileData = bytes of first upload. handleSend → callAPI always edits videoFileData. handleUpload already supports multi-file.
  • src/toolFunctions.js: ~15 result sites create blob URLs and addMessage({videoUrl}). Results are not tracked as media anywhere.
  • src/db.js is server MySQL (users/chat logs) — client media persistence is a separate concern.

Spec

  • 1. Media model. mediaItem = { id, kind: 'original'|'result', name, mimeType, isAudio, durationSec, thumbUrl, createdAt, prompt? }. Keep bytes in a Map<id, Blob> outside React state (perf); meta in state. New state: activeMediaId; selected row highlighted.
  • 2. Selection wiring. handleUpload: assign ids; if nothing selected, select the first new item. handleSend: resolve bytes for activeMediaId (fallback: first original) and pass to callAPI instead of always using videoFileData. Rail row click → setActiveMediaId(id); composer shows which source the next edit will use.
  • 3. Result tracking. Add registerResultMedia({blob, mimeType, label, prompt}); call it at each result site in toolFunctions.js (or wrap the videoUrl addMessage path). New items appear under "Recent jobs" the moment the chat result appears. Result click → preview + actions: Download, Use as source (sets active → enables edit chaining).
  • 4. Thumbnails (client-side, no server). Hidden <video src=blobUrl> → seek to min(1s, 10% duration) → draw 160×90 to canvas → toDataURL('image/jpeg', 0.7). Lazy per row, cached by id, fallback tile on error. Duration from loadedmetadata; audio gets a static icon tile.
  • 5. Persistence (IndexedDB — separate from server MySQL). DB finalcap-media, store items: {id, meta, bytes}. Rehydrate on load: recreate blob URLs, lazy thumbs. LRU eviction ~500MB, oldest results first. Rail survives reload with selection intact.
  • 6. + Add media. Reuses handleUpload. Keep the composer's attach button too — same handler.

Non-goals

  • No server/API changes; no tool-definition changes; chat flow unchanged (results appear in chat and rail).
  • Do not build this mockup's "Apply to: original / latest result" dropdown — rail selection supersedes it; unify on activeMediaId.

Acceptance

  • Upload 2 videos → 2 rows with thumbs + durations; select the 2nd → next prompt edits the 2nd clip.
  • Run an edit → result lands in Recent jobs alongside the chat message; "Use as source" chains a second edit onto the result.
  • Reload → rail repopulates from IndexedDB, selection preserved.
  • No console errors; existing test suite passes.
